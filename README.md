# Wochenzettel

AI-assisted meal planner and grocery app for Germany — plans a budget-optimized
weekly menu, tracks pantry stock, and generates a shopping list grouped by aisle.

Native Android app built with Kotlin, Jetpack Compose, Room, and Firebase
(Auth + Firestore sync). Weekly plans are generated by Gemini, with Groq as a
free-tier fallback and a bundled offline recipe set if neither is configured.

## Prerequisites

- [Android Studio](https://developer.android.com/studio) (Narwhal or newer)
- JDK 11+ (Android Studio bundles a compatible JDK; Gradle will also
  auto-provision one via the toolchain resolver)
- A [Firebase](https://console.firebase.google.com/) project (free Spark plan
  is enough) — required for sign-in and cloud sync

## 1. Clone

```bash
git clone https://github.com/Jeevanmerkaji/wochenzettel.git
cd wochenzettel
```

## 2. Firebase setup

The app's `applicationId` is `com.aistudio.wochenzettel.kmfzpz` (see
`app/build.gradle.kts`).

1. Create a Firebase project (or reuse one you own).
2. Add an Android app to it using the `applicationId` above.
3. Download the generated `google-services.json` and place it at
   `app/google-services.json`. This file is gitignored — every developer/
   clone needs their own copy from their own Firebase project.
4. In the Firebase console, enable:
   - **Authentication** → Sign-in method → Email/Password, and Google
   - **Firestore** (used for syncing plans/pantry/preferences across devices)

Without `google-services.json`, the build still succeeds
(`missingGoogleServicesStrategy = WARN`), but sign-in and cloud sync won't
work — the app falls back to local-only Room storage.

## 3. Configure secrets

Copy the example env file and fill in your own keys:

```bash
cp .env.example .env
```

| Key | Required | Notes |
|---|---|---|
| `GEMINI_API_KEY` | For AI-generated plans | Get one at [Google AI Studio](https://aistudio.google.com/apikey) |
| `GROQ_API_KEY` | Optional | Free-tier fallback, no credit card — [console.groq.com/keys](https://console.groq.com/keys). If set, tried before Gemini |
| `GOOGLE_WEB_CLIENT_ID` | For Google Sign-In | The **Web application** OAuth client ID from Firebase Console → Authentication → Sign-in method → Google → Web SDK configuration (not the Android client) |

If none of the AI keys are set, the app still runs using the bundled offline
recipe fallback. `.env` is read at build time by the Secrets Gradle Plugin and
is gitignored.

## 4. Signing (release builds only)

Debug builds sign automatically with the standard Android debug keystore — no
setup needed. `./gradlew assembleDebug` and running from Android Studio work
out of the box.

Release builds (`app/build.gradle.kts` → `signingConfigs.release`) expect a
keystore, sourced from either:

- `KEYSTORE_PATH`, `STORE_PASSWORD`, `KEY_PASSWORD` environment variables, or
- a `my-upload-key.jks` file in the project root (gitignored)

with key alias `upload`. Generate your own keystore if you don't have one:

```bash
keytool -genkey -v -keystore my-upload-key.jks -keyalg RSA -keysize 2048 -validity 10000 -alias upload
```

## 5. Build & run

**Android Studio:** Open the project root, let it sync, then Run on an
emulator or device (min SDK 24).

**Command line:**

```bash
./gradlew assembleDebug      # build a debug APK
./gradlew installDebug       # build and install on a connected device/emulator
./gradlew test               # unit tests (JVM, Robolectric)
./gradlew connectedAndroidTest  # instrumented tests (needs a device/emulator)
```

Screenshot tests use [Roborazzi](https://github.com/takahirom/roborazzi);
recorded screenshots live under `app/src/test/screenshots`.
